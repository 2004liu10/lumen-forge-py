提升画质（内置引擎）

这里列出还没提升画质的视频结果，勾选（或全选）后点「一键提升」即可。 除了程序自己生成的视频，也可以在下面贴一个本机文件夹路径，把里面的视频一起列出来（来源标「本地」）。 固定跑Chronos 插帧到 60fps → Proteus 放大 2×（1080p → 4K，恢复压缩 80 / 恢复细节 60 / 锐化 10） → 质感调色 → H265/NVIDIA 出片这一套，不开运动模糊脱模。下面可以选质感，默认「不增亮」：只把皮肤最亮的那一档高光压回去，暗部和中调一点不动，不会越提升越白；想完全不动色调就选「自然」。 这一版刻意不追求「更锐」：放大倍数从 4× 降到 2×、锐化只给 10，为的是少出塑料感和振铃，画面更接近真实拍摄。 画质引擎已随软件一起安装，不需要另外装 Topaz。 提升后的文件统一存到「画质提升结果」目录（默认在输出目录的 topaz 文件夹，可在设置里改位置），原片不会被删，随时可在下方「已提升」里还原。

账号管理

去 RunningHub 拿 Key（用户中心 → API Key）↗

每个账号的 API Key 只保存在本机数据目录的 db.json 中，不会外传。并发上限默认 1：3 个账号即可同时跑 3 个视频任务。
「额度」是该账号每 24 小时可成功生成的次数（默认 1）：生成成功后扣一次，用尽即进入冷却、不再接单，满 24 小时后自动刷新并重新可用；填 0 表示不限制。

视频模型管理

剧本模型

「AI 编导」把剧本拆成分镜就靠这个模型。只要 OpenAI 兼容的 /chat/completions 接口都行。 智谱免费档实测：glm-4.5-flash 最守指令（分镜最长、地点不乱跳）， glm-4-flash-250414 常被代码围栏包住解析失败，别用。

想完全白嫖就把引擎换成本地豆包：它直接在你开着的豆包窗口里打字、把回复取回来， 不需要接口地址和 Key。实测它写分镜比免费对话模型听话得多（不会自己编故事、地点不漏）。 代价是每次编导都会占用豆包窗口（先点「新对话」清上下文），一版分镜约 10~30 秒。

注意：豆包窗口只有一个。豆包正在生成图片或视频时，编导会先停下来让路， 否则它一点「新对话」就把那个视频对话切走了，视频任务会永远等不到自己的片子。 想同时干活就临时切回云端模型。

写剧本是另一步：实测豆包拆 JSON 分镜很稳，但写故事很平 —— 给它一句题材， 拆出来就是几个平铺的动作；本地 GPT 反过来，故事有层次，可它守 JSON 格式容易跑偏。 所以可以分两层：本地 GPT 先写一版剧本 → 豆包把剧本拆成分镜。 只在「你给的不是完整剧本」时才触发，你已经贴了整份剧本就原样拿去拆，不会被改写。 写一版剧本实测 20~40 秒，失败会退回「直接按你给的题材拆」并如实说明。

素材接口管理

请求头名默认 Authorization，前缀默认 Bearer ，不需要可留空

随机直链接口（如 api.yujn.cn）：在分类的「线路地址」填接口地址（一行一个，失败自动换），请求后服务器 302 跳到一段随机 mp4 / 一张随机图片，程序连着请求「一次拉几条」次攒成一批供轮播翻看，每次刷新都是新内容。
随机短片线路池（原 App 的做法）：线路域名集中在上面「全局线路池」里维护，每个分类只填一个短片编号，程序自动拼成 基地址/编号.m3u8。节点域名整批失效时，只改全局线路池一处，所有分类跟着换。
普通接口：在分类的「线路地址」里填完整列表接口（JSON 里「列表路径 / 地址字段」留空会自动推断），不走全局线路池。
线路按顺序试、失败自动换下一条，并记住上次能用的那条；随机源每请求一次就是另一段素材，m3u8 靠内置 hls.js 播放、下载自动合并分片，随机直链直接播放、下载原样保存。
「列表路径 / 地址字段」只对普通接口有效；地址字段留空时优先挑名字不带 watermark 的地址。
